# Audio Haptics — هزاز عبر السماعات (SM-T505N / LineageOS 24 / Android 17)

وحدة LSPosed تستبدل مدير الهزاز الفارغ في `system_server` بهزاز وهمي يشغّل الاهتزاز عبر السماعات.
النظام يرى هزازاً حقيقياً، فتعمل معه إعدادات الاهتزاز واهتزاز لوحة المفاتيح والإشعارات وكل التطبيقات.

> المشروع **لم يُترجم ولم يُجرَّب على جهاز** بعد: كُتب بالاعتماد على فحص `services.jar` و`framework.jar` من جهازك.
> توقّع تكرار واحد أو اثنين من التعديلات بعد أول تجربة.

## 1) بناء الـ APK (بدون حاسوب)
1. أنشئ مستودعاً جديداً على GitHub وارفع **كل** محتويات هذا المجلد (تأكد أن `.github/workflows/build.yml` ارتفع؛
   إن تجاهله الرفع من المتصفح فأنشئه من Actions ← *set up a workflow yourself* والصق محتواه).
2. تبويب **Actions** ← شغّل `build` ← بعد انتهائه نزّل الـ artifact باسم `AudioHaptics-apk` وفكّ ضغطه.

## 2) التثبيت
1. ثبّت الـ APK.
2. LSPosed ← Modules ← فعّل **Audio Haptics** ← النطاق: **System Framework** ← أعد تشغيل الجهاز.
3. افتح التطبيق: يجب أن يظهر «✔ النظام يرى الآن هزازاً». اضغط «منح صلاحية الحفظ عبر root» مرة واحدة.
4. جرّب أزرار الاختبار، ثم اكتب في الحقل لتجربة اهتزاز لوحة المفاتيح (من إعدادات النظام ← الصوت والاهتزاز).

## 3) التشخيص (الإصدار 0.2)
افتح التطبيق بعد الإقلاع: يعرض **تقرير system_server** مراحل التشغيل دون حاجة لـ logcat:
- `1.loaded` الوحدة دخلت system_server (غيابه = الوحدة غير مفعّلة أو النطاق خاطئ).
- `2.hooks` ما نجح من الـ hooks. `3.factory` هل رُكّب الهزاز الوهمي. `3b.service` المعرّفات التي يراها النظام فعلاً.
- `5.engine` و`6.audio` (يجب أن يظهر `perfMode=1`) و`7.on` عدد الطلبات التي وصلت للهزاز.

لقطة شاشة لهذا التقرير تكفي لتحديد الخلل بدقة. ولا تنسَ زر «منح صلاحية الحفظ عبر root».

## 4) الإعدادات (الإصدار 0.4)
- **الزر الرئيسي**: يوقف كل الاهتزاز عبر السماعات فوراً ويوقف مسار الصوت (توفير للبطارية).
- **إيقاف عند الوضع الصامت**: لا اهتزاز عندما يكون الرنين على «صامت» (وضع «اهتزاز» يبقى مسموحاً).
- **القوة / النغمة / النعومة**: القوة مستقلة؛ خفّض النغمة وزد النعومة لتقليل الصوت المسموع.
- **طور السماعات**: «هادئ» يشغّل اليسار واليمين بطور معاكس فيلغي معظم الصوت المنتشر في الغرفة ويبقى الاهتزاز في الهيكل (يُحس كتأرجح خفيف)، و«قوي» أقوى لكنه أعلى صوتاً.
- **مصدر الصوت**: «ثابت (BEACON)» مسار «يُبث عبر السماعة فقط» بمنحنى ثابت 0dB فلا يتأثر بأي مستوى صوت؛ إن لم يعمل على نظامك يتحول تلقائياً إلى «المنبّه». السطر `6.audio` في التقرير يبيّن ما اختير فعلاً.
- حماية السماعات: محدّد ناعم للذروة، والاهتزاز المتواصل محدود بـ60% من السعة وبـ30 ثانية.

## 5) الإنقاذ إذا حدث خلل
- حماية تلقائية: بعد 3 إقلاعات فاشلة متتالية تعطّل الوحدة نفسها.
- يدوياً (adb أو recovery): `touch /data/system/audiohaptics.disable` ثم أعد التشغيل.
- أو عطّل الوحدة من LSPosed، أو أقلع في الوضع الآمن فيعطّل Magisk الوحدات.

## 6) المراحل التالية (مقترحة)
1. قياس التأخير الفعلي وتقليله: تفعيل MMAP (العتاد جاهز: `MM_NOIRQ` و`audio.primary.bengal` يدعمانه) بتعديل `audio_policy_configuration.xml`.
2. إيقاظ استباقي عند لمس الشاشة بدل الاعتماد على «الشاشة تعمل».
3. دعم PWLE/Envelope، وتعويض الصوت ليستقل تماماً عن مستوى المنبّه.
